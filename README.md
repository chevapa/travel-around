# Атлас поездок — Загреб и окрестности

Интерактивная карта поездок: где были, что понравилось, куда планируем.
81+ точек по Хорватии, Словении, Италии и Венгрии.

## 🆕 Как добавить новое место

**Просто положи `.json`-файл в папку [`places/`](places/) — сайт подхватит его сам.**

1. Открой папку [`places/`](places/) в репозитории на github.com.
2. Нажми **Add file → Create new file**.
3. Впиши имя файла, например `ozalj.json` (латиницей, обязательно `.json`).
4. Вставь содержимое в таком виде:
   ```json
   {
     "name": "Озаль",
     "q": "Ozalj",
     "lat": 45.6333,
     "lng": 15.5667,
     "cat": "plan",
     "cats": ["castle", "view", "water"],
     "country": "hr",
     "season": "all",
     "drive": "50 мин",
     "note": "Замок на скале над Купой, рядом Мунярa (старая ГЭС, похожа на замок)."
   }
   ```
5. Нажми **Commit changes**.
6. Через 1–2 минуты открой сайт (или обнови страницу, F5) — точка появится на карте автоматически. Редактировать `index.html` не нужно.

Полный список полей и правила (обязательные/необязательные, допустимые значения) — в [`places/README.md`](places/README.md).

## Что умеет

- **Фильтры**: статус (понравилось / так себе / ещё не были), страна, сезон, 12 типов мест
- **Контуры времени в пути** — 1, 2 и 3 часа от Загреба, построены по реальным замерам
- **Время в пути** до каждой точки, уточняется через OSRM при наличии сети
- **«Что рядом»** — один запрос отдаёт времена до всех соседей в радиусе 70 км, результат кешируется
- **Добавление своих мест** с выбором точки прямо на карте
- **Предупреждения** «проверить перед выездом»: реконструкции, часы работы, сезонность
- Клик по названию — поиск в Google на местном языке

## Как выложить на GitHub Pages

Git и командная строка не нужны, всё делается в браузере.

1. Создайте новый репозиторий на github.com (кнопка **New**), назовите например `travel-around`, сделайте его **Public**.
2. На странице пустого репозитория нажмите **uploading an existing file**.
3. Перетащите туда `index.html`, `styles.css`, `.nojekyll` и папку `places/`
   (файл `README.md` по желанию). Без `styles.css` сайт откроется без
   оформления — вся вёрстка (риso-стиль, мобильная адаптация) в этом файле.
   Если `.nojekyll` не перетаскивается — его можно пропустить, для одностраничного сайта он не критичен.
4. Нажмите **Commit changes**.
5. Откройте **Settings → Pages**, в разделе *Build and deployment* выберите
   Source: **Deploy from a branch**, Branch: **main**, папка **/ (root)**, нажмите **Save**.
6. Через 1–2 минуты сайт будет доступен по адресу
   `https://chevapa.github.io/travel-around/`

## Почему на Pages лучше, чем в чате

В песочнице чата внешние запросы могут блокироваться, и тогда время в пути
показывается по зашитым значениям. На GitHub Pages таких ограничений нет —
OSRM отвечает нормально, и время считается по реальным дорогам.

## Где хранятся ваши данные

Добавленные места и кеш маршрутов лежат в `localStorage` вашего браузера.
Они не уходят на сервер и не попадают в репозиторий, но привязаны к конкретному
браузеру и устройству. Чтобы перенести — экспортируйте вручную через консоль:

```js
copy(localStorage.getItem('trip-atlas-custom-places'))
```

## Обновление списка мест

### Способ 1 (рекомендуется) — папка `places/`

См. раздел **«Как добавить новое место»** в начале файла: кладёшь
`.json`-файл в [`places/`](places/) — сайт подхватывает сам, без правки кода.

### Способ 2 — базовый набор в `places/base-*.json`

Исходные 81 точка (личный дневник поездок + подборка по итогам ресёрча)
раньше лежали хардкодом прямо в `index.html`, в массиве `PLACES`. Теперь
они вынесены в 4 файла в [`places/`](places/) — по тем же правилам, что
и обычные файлы из «Способа 1»:

- `places/base-visited-loved.json` — были, понравилось (31)
- `places/base-visited-ok.json` — были, так себе/нейтрально (11)
- `places/base-plans.json` — топ-планов из первого ресёрча (15)
- `places/base-research-east.json` — вторая волна ресёрча, восток региона (24)

Редактируются точно так же, как остальные файлы в `places/` — через
**Edit** (значок карандаша) прямо на github.com, без правки `index.html`.
Массив `PLACES` внутри `index.html` теперь всегда пустой (`const PLACES = [];`)
и заполняется в браузере при загрузке страницы. Поля и допустимые значения —
в [`places/README.md`](places/README.md#поля-и-допустимые-значения).

**Важный нюанс:** эти 4 файла грузятся напрямую по имени (через
`raw.githubusercontent.com`), а не через листинг папки `places/` (это
отдельный вызов GitHub API с более щедрым и не общим лимитом). Поэтому
если лимит API на листинг папки будет исчерпан, «community»-файлы в
`places/` (способ 1) на время перестанут подхватываться, а базовый набор
всё равно загрузится. Если переименовать любой из 4 файлов — обновите
список `BASE_FILES` в `index.html`, иначе файл продолжит подхватываться
через общий листинг папки (просто чуть более медленным путём), а не
пропадёт совсем.

## Источники

Карта — OpenStreetMap. Маршруты — публичный демо-сервер OSRM
(`router.project-osrm.org`), у него есть ограничения на нагрузку;
для интенсивного использования стоит поднять свой инстанс.
