# Папка `places/` — добавление мест без правки index.html

Любой `.json`-файл, положенный в эту папку через GitHub (drag & drop +
Commit changes), автоматически подхватывается сайтом при загрузке
страницы. Редактировать массив `PLACES` в `index.html` больше не нужно.

## Как добавить место

1. Откройте репозиторий `chevapa/travel-around` на github.com.
2. Зайдите в папку `places/`.
3. **Add file → Create new file**, назовите файл например `ozalj.json`
   (латиницей, без пробелов, обязательно расширение `.json`).
4. Вставьте содержимое по образцу `_example.json` (см. ниже).
5. **Commit changes** — прямо в main.
6. Через 1–2 минуты (обновление GitHub Pages) откройте сайт и
   обновите страницу (F5) — точка появится на карте автоматически.

Файлы, чьё имя начинается с `_`, игнорируются (используются под
шаблоны/примеры — как этот `_example.json`).

Один файл может содержать один объект-место `{...}` или массив
`[{...}, {...}]`, если хотите добавить сразу несколько точек одним
файлом.

## Поля и допустимые значения

| Поле | Обязательное | Назначение |
|---|---|---|
| `id` | нет | стабильный уникальный идентификатор места — случайная строка (напр. `b7nmno2d`), ничего не выражает, просто должна быть уникальной. Если не указан — сайт сгенерирует его сам при загрузке. К нему привязывается история взаимодействий (лайки/визиты/свайпы), поэтому если вы всё же прописали `id` вручную — старайтесь не менять его потом |
| `name` | да | название по-русски |
| `lat`, `lng` | да | координаты (десятичные градусы) |
| `q` | нет | название на местном языке — для поиска в Google по клику |
| `cat` | нет | статус: `loved` / `ok` / `plan` (по умолчанию считается план) |
| `cats` | нет | массив типов места (см. список ниже), напр. `["castle","view"]` |
| `country` | нет | код страны (см. список ниже) |
| `season` | нет | `all` / `warm` / `summer` / `stork` |
| `drive` | нет | время в пути от Загреба (текст, напр. `"50 мин"`) |
| `note` | нет | описание |
| `warn` | нет | что проверить перед выездом |
| `wantReturn` | нет | `true`/`false` — звёздочка «хотим вернуться» |
| `src` | нет | источник: `journal` (личный опыт) или `research` (подборка/ИИ-ресёрч, по умолчанию, если поле не указано) |
| `source` | нет | ссылка/название источника информации о месте (напр. `"Putni Kofer"`), когда это отдельно важно от `src` выше — см. `docs/place-content-model.md` |

**Про `meta`:** этого поля больше нет в контракте — см.
`docs/place-content-model.md` (issue #4/#43). Раньше оно использовалось для
трёх разных вещей в разных файлах (дата+способ поездки, дубликат `drive`,
атрибуция источника) без единого смысла; каждая теперь на своём месте
(история посещений — вне `places/*.json`, `drive`, `source` соответственно).

**Важно про `src`:** на сайте есть фильтр «Источник», и по умолчанию видны
только места с `src: "journal"` — всё остальное (включая файлы без поля
`src` вообще) скрыто за фильтром до тех пор, пока его не включат вручную.
Если хотите, чтобы добавленное место было видно сразу всем по умолчанию —
укажите `"src": "journal"`. Если это скорее предположение/подборка для
проверки — оставьте как есть или укажите `"src": "research"` явно.

```
town     — Город / городок
castle   — Замок / крепость
museum   — Музей / этнография
church   — Церковь / сакральное
nature   — Природа / хайк
view     — Смотровая
water    — Озеро / река
cave     — Пещера
beach    — Пляж / море
food     — Еда / вино
bike     — Велотема
spa      — Термы
culture  — Культура / история
```

### Допустимые значения `country`

```
hr — Хорватия
si — Словения
it — Италия
hu — Венгрия
mk — Сев. Македония
ba — Босния и Герцеговина
me — Черногория
rs — Сербия
al — Албания
```

Нужна страна, которой нет в списке? Добавьте её в справочник `COUNTRIES`
в `index.html` — точно так же, как в `CATEGORIES` для новых типов места
(это единственное, что нельзя сделать одним JSON-файлом — нужна правка
кода на 1–2 строки).

**Если указать значение не из списка** (опечатка или новый тип, который
ещё не добавлен) — сайт не сломается: такая точка просто покажет
значение как есть, без иконки/флага, вместо привычного вида. Но лучше
использовать значения из списка, чтобы всё выглядело аккуратно и
единообразно.

## Технические детали (на будущее / для понимания)

При загрузке страницы index.html делает запрос к публичному GitHub
API (`GET /repos/chevapa/travel-around/contents/places`), получает
список файлов в этой папке, скачивает каждый `.json` и добавляет
описанные в нём места на карту. Запрос анонимный (не нужен токен),
но у GitHub API есть лимит ~60 запросов в час на IP — для личного
использования этого с большим запасом достаточно. Если лимит вдруг
будет исчерпан, страница молча пропустит только *новые* файлы из этой
папки — ничего не сломается, ошибка проглатывается тихо.

**Отдельно про базовый набор** (`base-visited-loved.json`,
`base-visited-ok.json`, `base-plans.json`, `base-research-east.json` —
тоже лежат в этой папке): они не зависят от лимита листинга папки выше,
т.к. грузятся напрямую по известному имени файла через
`raw.githubusercontent.com` (см. `loadBasePlaces()` в `index.html`) —
у этого пути свой, более щедрый лимит. Поэтому даже при исчерпанном
лимите API базовый набор (81 точка) почти всегда загрузится, а вот
дополнительные файлы, добавленные через «Способ 1» (drag & drop нового
`.json`), могут временно не появиться до сброса лимита.

Если со временем файлов в папке станет очень много (полсотни+) и
подгрузка ощутимо замедлится — можно будет заменить этот механизм на
один собранный `places.json` (склеенный GitHub Action при каждом
коммите), сохранив тот же пользовательский сценарий «просто кинуть
файл в папку».
